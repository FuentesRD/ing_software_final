1. Resumen

La base de datos biblioteca almacena el sistema de gestión de biblioteca escolar. Las tablas se generan con las migraciones de Django a partir de los modelos de cinco apps (cuentas, catalogo, prestamos, multas y notificaciones). Este documento se generó leyendo information_schema del servidor y los metadatos de los modelos, por lo que refleja el esquema tal como existe.

2. Convenciones del esquema

AspectoConvención
Llaves primariasid BIGINT AUTO_INCREMENT (BigAutoField). Excepción: estudiante y profesor usan usuario_id como llave primaria (relación uno a uno).
Llaves foráneasColumna <relación>_id de tipo BIGINT, con índice. Nombre de la restricción generado por Django: <tabla>_<columna>_<hash>_fk_<tabla_ref>_id.
Comportamiento al borrarEn MySQL todas las llaves foráneas tienen ON DELETE NO ACTION. El comportamiento real lo aplica Django según on_delete: PROTECT impide el borrado, CASCADE borra en cascada y SET_NULL deja la columna en NULL. Si se borra con SQL directo, MySQL rechaza el borrado de cualquier fila referenciada.
Valores por defectoDjango aplica los valores por defecto al crear objetos; las columnas no tienen cláusula DEFAULT en MySQL. Al insertar con SQL directo hay que dar todos los valores obligatorios.
Dominios (estados, tipos, motivos)VARCHAR con restricción CHECK ... IN (...) llamada ck_<tabla>_<campo>, que coincide con las TextChoices del modelo. Se prefirió a ENUM para poder cambiar valores con migraciones.
BooleanosTINYINT(1): 0 = falso, 1 = verdadero.
Fechas y horasDATETIME(6) con microsegundos, guardado en UTC (USE_TZ = True); Django convierte a America/Mexico_City al mostrar. Las fechas sin hora (fecha_vencimiento, fecha_adquisicion) son DATE.
MontosDECIMAL(10,2) u DECIMAL(8,2); nunca FLOAT, para evitar errores de redondeo.
Enteros no negativosLos campos PositiveSmallIntegerField se crean como SMALLINT UNSIGNED con un CHECK >= 0 generado por Django (<tabla>_chk_N).
Baja lógicausuario.is_active y libro.activo; los préstamos, multas y pagos nunca se borran (RN-16).

9.3 Saldo de multas pendientes

Monto, pagos parciales y saldo de cada multa pendiente (CU-14, CU-28). Equivale a Multa.saldo().

SELECT u.username, m.motivo, m.monto,
       COALESCE(pg.pagado, 0)            AS pagado,
       m.monto - COALESCE(pg.pagado, 0)  AS saldo
FROM multa m
JOIN usuario u ON u.id = m.usuario_id
LEFT JOIN (SELECT multa_id, SUM(monto) AS pagado
           FROM pago GROUP BY multa_id) pg ON pg.multa_id = m.id
WHERE m.estado = 'PENDIENTE'
ORDER BY saldo DESC;
